# 一次运行：只看那份名单

这份只讲一件事：**那份员工名单，从你打开网页到按 F5，中间都经历了什么。**

不用背任何新词。文里出现的英文都是代码里原本就有的名字，照着念就行。看完只要记住最后那句话。

---

## 开场：先认三样东西

不是三个概念，就是三份数据：

| | 是什么 | 谁在用 |
| --- | --- | --- |
| **① 文件里写死的 10 条** | 程序员手打在 `src/data/index.js` 里的 10 个假员工，不是从数据库或接口来的 | 一开始用 |
| **② 屏幕上正在用的那份** | React 替页面记着的 | **界面长什么样，只看它** |
| **③ 浏览器里存的一行字** | 把 ② 转成文字存下来的「照片」 | **表格第一次出现时**读一次（打开页面、登录、登出再登录、按 F5，都算一次） |

### 「写死的 10 条」到底是什么

就是**手打在源码里的 10 个假员工**。打开 `src/data/index.js`，第 1～82 行全是它，长这样（只贴头尾两条）：

```js
const employeesData = [
  {
    id: 1,
    firstName: 'Susan',
    lastName: 'Jordon',
    email: 'susan@example.com',
    salary: '95000',
    date: '2019-04-11',
  },
  // ……中间还有 8 条，格式一样……
  {
    id: 10,
    firstName: 'Lyndsey',
    lastName: 'Follette',
    email: 'lyndsey@example.com',
    salary: '110000',
    date: '2020-01-15',
  },
];

export { employeesData };   // 第 84 行：交出去给别人用
```

每人 6 项：编号、名、姓、邮箱、工资、入职日期。邮箱全是 `@example.com`，一看就是编的示例数据。数组名叫 `employeesData`；`Dashboard/index.js:9` 把它拿进来，第 12 行让页面一开始就用**这一份**。

「写死」是说它**躺在源码文件里**：你改这个文件里的字，下次刷新才会变；而你在网页上新增、删除、编辑，改的是页面打开时造出来的那份，**这个文件一个字都不会变**。第一次打开、浏览器里还没存过东西时，表格显示的就是这 10 个人，所以也叫「种子」。

**贯穿全篇的一句话规矩**：屏幕只看 ②。③ 是一行文字，不是名单本人；你往里写多少次，都没人再去看它，除非表格重新出现（按 F5、或登出再登录）。

### 那为什么还要存 ③？

因为**网页一关（或按 F5），内存里那份就没了**，浏览器不会替你记着。所以每改一次都得写一行字，等下次打开时才有东西可读。像游戏存档：这一局里随时存档，但只在**重新开局**时读一次档——**存档不是给现在这一局用的，是给下一局用的**。

注意是「表格第一次出现就读一次」，**不是「总共只读一次」**：打开页面、点登录、登出再登录、按 F5，都会让表格重新出现一次，也就再读一次。

- **什么时候写**：Add / Edit / Delete 三处，每改一次写一次，**覆盖上一份**。名单这个 key 里永远只有一行、是最新那张照片。
- **当前这一局不用读**：手里已经有最新那份了，读回来反而另造一份新的，把当前状态打乱。
- **代价举例**：开两个标签页，A 改了写进去，B 不知道，B 刷新前一直显示旧的；B 再改一次还会把 A 的改动盖掉。

## ① 打开网页

| | |
| --- | --- |
| 发生 | 浏览器把 JS 跑一遍 —— 源码里那些字，到这一步才真的变成 10 个对象、装进数组 |
| 名单 | 那 10 条被造出来，编号 1 到 10 |
| 屏幕 | 登录框 |
| 代码 | `src/data/index.js`、`App/index.js:7` |

**记一句**：文件躺在硬盘上只是文本，浏览器跑一遍才造出对象；这个文件整个页面只跑这一次。第 ⑤ 步会用到。

---

## ② 输入账号密码，点登录

| | |
| --- | --- |
| 发生 | App 里那个开关从「没登录」变成「已登录」；这块地方原来放登录框，现在改放表格 |
| 名单 | 一开始用的就是文件里那 10 条（**同一份，不是复印**）；紧接着表格刚出现时去读一次浏览器里那行字，存过就换成从字里还原出来的**另一份** |
| 屏幕 | 首次打开是 10 行；之前存过东西的话，是存档里的条数 |
| 代码 | `Login/index.js:21-31`、`Dashboard/index.js:12,17-20` |

**记两句**：

- 「去浏览器里读那行字」**表格每出现一次，就读一次**。之后你增删改多少次都不会再读；除非按 F5、或者登出再登录，让表格重新出现一遍。
- 从字里还原出来的是**新造的一份**，跟当初存进去的那份不是同一个东西。

### 为什么这里表格是「第一次被造出来」

登录前这块地方放的是登录框，表格从来没出现过。React 每次重新算的时候只看一件事：**这块地方现在该放什么**。

- 还是原来那种东西 → 沿用，只改里面的内容；
- 换成另一种东西了 → 把旧的拆掉，新造一个。

登录成功是第二种情况，所以表格只能是新造的。

**但页面上不止一个「位置」，每个位置各管各的**：

| 位置 | 谁管 | 可以放什么 |
| --- | --- | --- |
| 最外面那个 | `App/index.js:15-19` | 登录框 **或** 表格 |
| 表格里面那个 | `Dashboard/index.js:58-85` | 表+按钮 **或** Add 表单 **或** Edit 表单 |

所以点 Add 的时候：

- 最外面那个位置**还是表格、没换**，App 这一层确实没动；
- 但里面那个位置从「表+按钮」换成了「Add 表单」——表和按钮被**拆掉**，**Add 第一次被造出来**（登录页里根本没有它）；
- 提交之后反过来：Add 被拆掉，**表和按钮重新造出来**。

最后这一条就是第 ④ 幕「屏幕为什么会多出一行」的真正原因：表格是重新造的，所以它从第一行开始读那份名单。

顺带一句：登录框被拆掉时，你刚输的账号密码也没了——不是谁清空了它，是**那个框本身不在了**。同理，下次再点 Add 看到的是空表单，因为上一个 Add 已经被拆掉了。

> 什么时候才是「同一个东西只重新画一遍」？**删掉一行**就是：表还留在原位没换，只是重新算一遍，编号被刷成 `1..9`。见第 ③ 幕。

## ③ 表格第一次画出来

| | |
| --- | --- |
| 发生 | 表格代码最上面三行，把每个人的 `id` 改成了他排第几 |
| 名单 | 人还是那些人，但编号被刷成 `1,2,3,…` 连续 |
| 屏幕 | No. 列是 1,2,3…；每行按钮上带着这个编号 |
| 代码 | `Table.js:4-6` |

**记一句**：所以这个 `id` 不是「工号」，是「**他现在排第几**」。删掉中间一个人，后面所有人的编号都会变。

（删一行时，名单会被换成**新的一份**——跟第 ④ 幕「直接往里塞」不一样；但表格还留在原位、只是重新算一遍，所以编号照样被刷。）

---

## ④ 点 Add，填完提交（最要紧的一步）

跟名单有关的六步，按代码顺序（跑完这六步还有个 1.5 秒的成功提示，`Add.js:38-44`，跟名单无关）：

1. 五个输入框，每个自己记着自己那点字 —— 跟名单无关。
2. 算出新编号 = 现在人数 + 1，造一个人。
3. `push` —— **直接往「屏幕上正在用的那份」里塞一个**，变成 11 条。
4. 把这 11 条转成一行字，存进浏览器。
5. `setEmployees(employees)` —— 交上去的还是同一份，React 一看没换东西，**没理它**。
6. `setIsAdding(false)` —— 另一个开关变了，Dashboard 里那个位置要放的东西换了：Add 表单被拆掉，**表格重新造出来** → 它从第一行开始读那份名单 → 读到 11 条。

| | |
| --- | --- |
| 名单 | 还是原来那份，里面多了 1 条 |
| 屏幕 | 11 行 |
| 代码 | `Add.js:23-36` |

**记三句**：

- 名单变多，靠的是第 3 步「直接往里塞」。
- 屏幕多出第 11 行，靠的是第 6 步「表格被重新造出来」——**不是谁把第 11 行插进了旧表格，是旧表格整个不在了、新表格从头读了一遍**。
- 第 4 步存进浏览器，跟**这一次**屏幕变不变一点关系都没有，它只管下一次表格出现（通常是按 F5）。

**一个特别容易想反的地方**：假如第 3 步改成「另造一份 11 条的名单」，却漏了第 5 步，屏幕会**停在 10 行**。因为 React 记着的还是旧那份；新造的那份没人交给它，这段函数一跑完就丢了。存进浏览器也救不了——那只是一行字，不会自己跑回来。

## ⑤ 按 F5

| | |
| --- | --- |
| 发生 | 页面整个重来 → 文件再跑一遍 → 写死的那 10 条重新造出来 → 第 ② 步再来一次 |
| 名单 | 浏览器里存过 → 换成从字里还原的那份；存的是**空的** → 那段判断不成立，**保持 10 条种子** |
| 屏幕 | 一般是上次的数据；但如果你把人删光了，10 条会自己回来 |
| 代码 | `App/index.js:9-11`、`Dashboard/index.js:12,17-20` |

**记一句**：刷新 = 第 ② 步重播一次，第 ③ 步刷编号也会再来一次。

**为什么刷新后不用重新输密码？** 登录时 `Login/index.js:22` 把 `is_authenticated` 也存进了浏览器。刷新后 App 开头先短暂显示登录框，紧接着它自己去读这一项、把开关设回「已登录」，表格就出现了——不是你又登录了一次。

## 自己跑一次，比读十遍管用

调试用的 6 行**已经全部加进项目了，不用你动手贴**。它们只往控制台打印一行字，不改任何数据；每条开头都有自己的名字，看名字就知道在说哪一步。

| 控制台里的名字 | 加在哪个文件 | 让你看到什么 |
| --- | --- | --- |
| `表格这时的名单` | `Dashboard/index.js` | 表格每次重新画，手里那份名单是几条、编号长什么样 |
| `从浏览器读回来的` | `Dashboard/index.js` 读存档的地方 | 这次打开页面，浏览器里到底存没存过东西 |
| `刷编号之前` / `刷编号之后` | `Table.js`，刷编号那三行的前后 | 编号怎么被刷成 1,2,3… |
| `新增之前` / `新增之后` | `Add.js`，提交时 | 名单从 10 条变 11 条 |

**怎么跑**：`npm start` → 等终端不再滚动 → 浏览器按 `Ctrl + Shift + R` → 按 `F12` 打开 Console。然后依次做：**看表 → 新增一条 → 删第 3 行 → 刷新**。打开就直接是表格也没关系，说明上次登录还在，照样往下做。

| 你做的 | 控制台应该出现 | 对应 |
| --- | --- | --- |
| 刚打开 / 刚登录 | `表格这时的名单 10 1,2,…,10`；`从浏览器读回来的 没有存过` | ② |
| 新增一条 | `新增之前 10 …` → `新增之后 11 1,…,10,11`；表格那句也跟着变成 11 条 | ④ |
| 删第 3 行 | `刷编号之前 10 1,2,4,…,11` → `刷编号之后 10 1,2,…,10` | ③ |
| 刷新 | 又从头打印一遍；之前删光过的话，回到 10 条 | ⑤ |

> **同一句连着出现两遍是正常的**，开发模式故意跑两遍，不是出错，不用管。
> 数字会随上一步叠加：跳过新增、直接删第 3 行，看到的就是 `1,2,4,…,10 → 1..9`。**看形状比背数字重要**：删完总是「缺一个号、最大值不变」，刷完总是「连续 1..N」。
> 之前跑过、浏览器里已有存档时，「从浏览器读回来的」会显示存档条数而不是「没有存过」，表格会紧接着再打印一次。

**这 6 行是临时的，跑完就没用了。** 分布在 `Dashboard/index.js`、`Table.js`、`Add.js` 三个文件里，搜 `console.log` 就能找到。**看完说一声，我帮你删干净**，不用自己动手。

> 顺带留个坑的记录：这类打印必须放在「名单被造出来之后」。放到它前面，页面会直接全白，报 `Cannot access 'employees' before initialization`——就是上次那个白屏。现在 6 行都在正确位置。

## 最后只要记住一句

> **屏幕永远只认「当前正在用的那一份」。浏览器里存的是它的一行文字照片，不是它本人。**
> 这一份可能被换掉（读回存档时、删一行时），但不管换过几次，屏幕只认当下这一份，不看浏览器里那行字。
> 往浏览器里存东西，只保证**下次打开**能看到；这一次屏幕变不变，只看重新算一遍时读到的那份变没变。

五步压成一行：

**① 10 条诞生 → ② 换成表格 + 读一次存档 → ③ 编号刷成行号 → ④ 直接塞一条 + 表格重新造一遍 → ⑤ 页面重来，② 重播**

## 附：以后看到这几个词，就是下面这个意思

不用背，碰到再回来查一眼。

| 别人（或我之前）会说 | 其实就是 |
| --- | --- |
| 挂载 / 重生 / 第一次出现 | 第一次被造出来、放进页面 |
| 重渲染 | 同一个东西还在，只是重新算了一遍界面 |
| 卸载 | 从页面拆掉，它自己记的东西全没了 |
| state 槽位 | React 替这个组件记着的那份数据 |
| 引用 | 「同一份东西」，不是复印一份 |
| bail out | React 一看没换东西，这次就不算了 |
| 不可变更新 | 另造一份新的，不改动原来那份 |
| props | 从外面传进来的那份数据 |

`docs/crud-app-primer.md` 是留着查阅的手册，词多、话绕，**先别看**。等这份读顺了、想深挖某个「为什么」，再按小节去查。
